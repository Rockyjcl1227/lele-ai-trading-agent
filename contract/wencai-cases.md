# 问财 Case 盘点

## 路由原则

先判断用户是否在讨论当前股票，再决定是否加载行情上下文。日常问答不得强制生成股票报告；金融数值不得由大模型编造。

## Case 矩阵

| Case | 示例 | 是否读取行情 | 输出形式 |
|---|---|---:|---|
| 日常问候 | 你好、你是谁 | 否 | 简短自然回复 |
| 通用问答 | 什么是市盈率 | 否 | 解释 + 示例 |
| 当前个股解盘 | 分析贵州茅台上午走势 | 是 | 多空报告 + 关键价位 |
| 指定时点分析 | 为什么 10:43 拉升 | 是 | 时点前走势 + 量价解释 |
| 技术指标 | KDJ 和 RSI 怎么看 | 是 | 指标卡 + 冲突说明 |
| 板块相对强弱 | 个股是否强于白酒板块 | 是 | 个股/板块/指数对比 |
| 持仓诊断 | 成本 1300 怎么处理 | 是 | 持有、减仓、止盈止损条件 |
| 买卖计划 | 什么位置可以买 | 是 | 条件区间 + 交易确认入口 |
| 异动预警 | 放量突破时提醒我 | 是 | 触发条件 + 提醒确认 |
| 午后推演 | 下午可能怎么走 | 是 | 上午实盘 + 三情景虚线 |
| 新闻事件 | 公告有什么影响 | 需要事件源 | 事件摘要 + 影响路径 |
| 数据不足 | 问未来一定涨多少 | 否 | 明确无法保证，改给条件分析 |

## 当前路由状态

- `greeting`：问候与寒暄，不加载行情。
- `help`：介绍问财能力与可用入口。
- `general`：股票无关的普通问题，接外部模型后直接回答。
- `data_gap`：必涨、稳赚等不可满足请求，转为条件和风险分析。
- `event`：公告、新闻、财报与事件，需要真实事件源。
- `signal`：异动、放量、突破和预警。
- `selection`：按题材、热度和量价条件筛选股票。
- `market`：指数、市场情绪与市场宽度。
- `sector`：所属板块、行业和同类股比较。
- `holding`：成本、仓位、浮盈亏与持仓动作。
- `trade_plan`：买点、卖点、止盈、止损和价格条件。
- `indicator`：MACD、KDJ、RSI、VOL、均线与 BOLL。
- `forecast`：午后、收盘和次日条件推演。
- `analysis`：当前个股或指定时点的综合解盘。

## 推荐 Skill

- `quote_snapshot`：读取当前股票午间快照。
- `intraday_pattern`：识别均价线、量价和分时形态。
- `technical_indicators`：计算 MACD、KDJ、RSI、VOL。
- `market_context`：比较指数、板块和同类股。
- `position_diagnosis`：结合成本、仓位和盈亏。
- `trade_plan`：生成支撑、压力、止损和触发条件。
- `signal_alert`：保存放量、突破、跌破等提醒。
- `event_lookup`：读取公告、新闻和公司事件。

## 优化优先级

1. 接入真实行情和服务端 DeepSeek 对话。
2. 为每只股票持久化独立会话。
3. 支持 SSE 流式回复和取消生成。
4. 对价格、指标和日期做服务端校验。
5. 增加引用来源、行情时间戳和数据延迟提示。
6. 对买卖建议增加风险等级与适当性提示。
